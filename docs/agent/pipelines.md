# 코어 경로

설치된 경로: `full` · `fix` · `quick` · `manual` · `docs`. 호출은 `/ax:<경로>` (`/ax:help`로 요약).
`style`(표현 변경)은 UI 코드가 생기면 추가한다.

## 단계 매트릭스

| 단계 | `full` | `fix` | `quick` | `docs` | `manual` |
|---|---|---|---|---|---|
| 접수 · 지시서 | 전체 | 간소 | 3줄 | 전체 | 간소(역추론) |
| 착수 단계 (신규 구축만) | ● | – | – | – | – |
| 구현 계획 | ● | 간소 | – | 목차 · 독자 | – |
| 성공 기준 · 테스트 계획 | ● | 실패 테스트 1개 | – | 확인할 주장 목록 | – |
| 문서 영향 분석 | ● | ● | – | 주 작업 | 불일치 보고 |
| 되돌릴 수단 확보 | ● | ● | ● | ● | 기준점 확인 |
| 구현 · 작성 | ● | ● | ● | ● | 사람이 완료 |
| 빌드 · 린트 게이트 | ● | ● | ● | 문서 게이트 | ● |
| 테스트 | ● | ● | 위험 신호 시 | 예제 실행 | – |
| 검토 | 코드 + 문서 | 코드 + 문서 | 위험 신호 시 | 사실 대조 | 가볍게 |
| 산출물 목록 대조 | ● | ● | – | ● | ● |
| 반영 (종료 지점까지) | ● | ● | ● | ● | ● |
| 환류 · 기록 | ● | ● | 한 줄 | ● | ● + 규칙 제안 |

화면 검토는 UI가 생기면 추가한다.

## 경로별 정의

- **`full` — 새 기능, 여러 모듈에 걸친 작업, 신규 구축.** 전 단계를 수행한다.
  - *착수 단계 (코드가 없는 지금은 첫 `full`이 해당):* 기술 스택과 구조를 제안 → **사람 승인** → 스캐폴딩 → `scripts/gate.sh`의 코드 게이트 구성 → `ARCHITECTURE.md`의 "주요 진입점" · `risk-signals.md`의 경로 확정. 이후 첫 기능부터는 일반 `full`이다.
  - *자율 실행 옵션:* 명세가 명확한 중형 작업은 검증자가 통과시킬 때까지 구현–검증을 반복할 수 있다. 반복 상한 **3회**(기본 가정, 바꾸려면 이 줄을 고친다).
- **`fix` — 버그, 간단한 개선.** 문서화는 줄이되 테스트와 검토는 그대로 둔다.
- **`quick` — 작고 위험이 낮은 수정.** 최소 diff와 게이트만 거친다. 위험 신호가 감지되면 최소 테스트와 검토가 켜진다.
- **`docs` — 문서가 주 산출물인 작업.** 독자와 범위 확정 → 작성 → 문서 게이트 → **사실 대조 검토** → 사람 확인 → 반영.
  - 문서 게이트(결정적): `bash scripts/gate-docs.sh` — 상대 링크 · 문서에 적힌 저장소 경로의 존재 검사.
  - 사실 대조: 검토자가 문서에서 "확인할 주장"을 뽑아 코드 · 설정과 대조하고 불일치 목록을 만든다.
  - 작업 중 코드 결함을 발견하면 고치지 않는다. 멈추고 별도 지시서를 제안한다.
  - 지시의 출처가 된 요구사항 문서는 사람이 요청한 `docs` 작업에서만 고친다.
- **`manual` — 사람이 이미 고친 것의 반영.** 기준점(직전 커밋)과의 차이를 읽고, 가벼운 검토 후 기능 단위로 정리해 반영한다. 변경의 의도를 역추론해 **향후 규칙으로 삼을지 제안**한다.

## 선택 규칙
1. 사람이 경로를 지정하면 그 경로에서 시작한다. 지정이 없으면 접수의 경로 초기값에서 시작한다.
2. 에이전트가 고를 때는 이유를 한 줄로 밝힌다. 애매하면 더 무거운 쪽을 고른다.
3. 어떤 경로든 위험 신호가 감지되면 승격하고 즉시 알린다 (`risk-signals.md`).
4. 작업 도중 범위가 커지면 멈추고 경로 변경이나 지시서 분할을 제안한다.
5. 하나의 지시서에 코드와 문서가 함께 있으면 코드 쪽 경로를 따르고, 문서는 같은 변경 집합에 넣는다.
