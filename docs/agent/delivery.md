# 산출 · 환류

## 산출물 목록
접수 때 지시서에 적고, 끝날 때 대조한다.

| 출력 유형 | 산출물 | 확인 방법 |
|---|---|---|
| 시스템 신규 | 스캐폴드, 게이트 스크립트 갱신, 첫 기능, 실행 방법 문서, `ARCHITECTURE.md` 갱신 | 빈 환경에서 문서대로 빌드 · 실행이 되는가 |
| 시스템 갱신 | 코드 변경, 테스트, 영향받는 문서 | 게이트 + 수용 기준별 증거 |
| 문서 신규 | 문서, 문서 지도에 등록 | 문서 게이트 + 사실 대조 |
| 문서 갱신 | 변경된 문서, 변경 요약 | 문서 게이트 + 변경된 주장만 사실 대조 |

## 경로별 문서 의무

| 경로 | 의무 |
|---|---|
| `full` | 문서 지도로 영향 분석 → 영향받는 문서를 **같은 변경 집합**에서 갱신. `ARCHITECTURE.md` 갱신 필요 여부 확인 |
| `fix` | 사용자가 보는 동작이 바뀌면 해당 문서 |
| `quick` | 변경 이력 문서는 두지 않으므로 의무 없음 |
| `manual` | 역추론한 의도를 기록. 문서와 코드의 불일치를 발견하면 보고 |
| `docs` | 문서가 주 산출물 |

## 문서 형식별 작업 방식

| 형식 | 작업 방식 | 검토 방식 |
|---|---|---|
| 저장소 안의 Markdown | 직접 수정 | 일반 diff |
| 저장소 밖 시스템 (위키 · Notion 등) | 초안만 `docs/agent/outbox/`에 작성 (직접 수정 금지) | 사람이 게시 |

지시의 출처가 된 요구사항 문서는 요청이 없는 한 고치지 않는다. 고쳐야 할 점은 질문 · 제안 목록으로 돌려보낸다.

## 작업 지시서 + 작업 기록 (`docs/agent/worklog/{ID}.md`)

```markdown
# {ID} {작업 제목}

## 지시서
- 출처: {채널} / {프롬프트 원문 · 문서 경로+해시}
- 요청자 / 실행자: {…} / 질문 · 환류 채널: {대화 · 문서 소유자}
- 유형: {신규 구축 / 기능 추가 / 결함 수정 / 변경 / 문서 작업}
- 요구 항목
  - {항목 ID}: "{원문 인용}" → 수용 기준: {…} / 확인 방법: {…}
- 확인된 값 · 가정: {조사로 확인한 것, 사람이 질의 인터페이스로 답한 것, 에이전트의 가정}
- 미해결 질문: {…}
- 범위 밖: {…}
- 읽지 못한 것: {…}
- 산출물 목록: {코드 / 테스트 / 문서별 신규 · 갱신}
- 환경 모드: 원격 VCS / 경로: {선택과 이유} / 위험 신호: {…}

## 기록
- 변경 집합: {브랜치 · 커밋}
- 게이트: {명령 → 결과}
- 검토: {판정과 근거}
- 추적표: {표 또는 링크}
- 환류: {어디에 무엇을 남겼는가}
- 되돌리는 방법: {한 줄}
- 남은 것: {미해결 사항, 발견했지만 건드리지 않은 문제}
```

## 추적표
`full` · `docs`와 문서 채널 작업에서 작성한다.

| 요구 항목 ID | 출처 위치 | 변경 (파일 · 커밋) | 검증 증거 | 문서 반영 | 상태 |
|---|---|---|---|---|---|
| {ID} | {절} | {…} | {명령 → 결과} | {문서명} | 완료 / 부분 / 보류 / 범위 밖 |

## 환류
지시가 들어온 채널로 돌려보낸다.

| 채널 | 환류 내용 |
|---|---|
| 프롬프트 | 대화로 요약: 한 일 · 가정 · 증거 · 남은 것. 되돌리는 방법 한 줄 |
| 문서 | 추적표와 질문 · 제안 목록을 문서 소유자에게. 임시 ID 목록 포함 |

환류는 읽는 사람 기준으로 쓴다. 개발자가 아닌 요청자에게는 파일명보다 "무엇이 어떻게 달라졌는지"를 먼저 말한다.

## 완료 정의
산출물 목록의 모든 항목이 *완료*이거나 사유가 적힌 *보류*이고, 게이트가 통과했고(건너뜀은 통과가 아니다), 환류가 끝났고, 되돌리는 방법이 기록되어 있다.
