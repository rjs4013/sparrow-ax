## 기록
- 변경 집합: 브랜치 `feat/WO-20261028-09-contract-collect-view` (WO-08 브랜치 위에서 분기, 커밋 1개). 사람이 DB 구조와 실호출(상한 40회)을 승인했다(2026-10-29, `AskUserQuestion`).
- 실수집 결과(승인된 실호출 1회): `npm run collect -- --from 2026-01-01 --to 2026-10-28 --max-calls 40` → 달력 월 10개 조회에서 423건 수신, **9개사 계약 11건 저장, 호출 21회**(상한 40 이내), 종료코드 0. 저장 결과를 업체별로 집계하면 코드마인드 4 · 스패로우 2 · 에스에스알 2 · 나일소프트 2 · 래브라도랩스 1건이고 조달청 계약(수요기관 자리표시자) 10건 · 기관 직접 1건이다. 이는 WO-20261028-07 5차의 올해 이력(11건, 같은 분포)과 일치한다. 응답 원문은 저장하지 않았다.
- 화면 확인: 개발 서버(`npm start`)를 띄워 브라우저에서 2026년 2월 · 6월 · 10월 월 화면을 눈으로 확인했다(표, 마지막 수집 상태 한국시간 표시, 수요기관 미공개 칩, 기관 직접 계약의 기관 이름, 제품 목록). 이후 제품 목록 접기와 보안 헤더 변경은 서버 주입 테스트로만 확인했고 브라우저로는 다시 보지 않았다.
- 게이트: `bash scripts/gate.sh` → 종료코드 0, 건너뜀 없음, build · lint · test(검토 전 93개 통과 + 검토 반영 테스트 추가) · `npm audit`(high 이상). 이 기록 작성 시점의 최종 수치는 아래 "최종 게이트" 줄.
- 검토: `reviewer`(별도 컨텍스트) 통과, 차단 없음, 중요 1건. 반영한 것: ① 호출 상한에 재시도 중 닿으면 직전 오류를 메시지에 남기고 불필요한 대기를 하지 않음(테스트 추가), ② 공동수급 계약의 합계 이중 계상 제거(계약번호 단위로 합산, 테스트 추가), ③ 제품 식별번호가 비면 "목록 밖" 대신 "제품 정보 없음", ④ CSP에 `form-action` · `base-uri` · `frame-ancestors`와 `X-Content-Type-Options` 추가, ⑤ `--max-calls` 상한 1000, ⑥ ARCHITECTURE의 낡은 서술 2곳 정리. **반영하지 않은 것(다음 지시서에서 다룬다):** 실패한 실행의 수신 · 매칭 건수가 0으로 기록됨, `finishRun` 자체가 실패하면 실행 기록이 `running`으로 남음, upsert만 하므로 삭제 · 재분류가 반영되지 않음(증분 수집에서), 금액이 소수면 천 단위 구분이 어긋날 수 있음(원화 정수라 발생하지 않음), `main.ts` 명령은 단위 테스트가 없고 입력 검증은 코드 검토로만 확인했다.
- 범위 밖이지만 한 변경(사유): `src/web/main.ts`의 `DB_PATH` · `HOST` · `PORT`를 `??` 대신 `||`로 읽는다(`env.example`를 복사해 값을 비워 둔 `.env`에서 빈 문자열이 기본값을 가리지 않게). `.claude/launch.json`은 브라우저 미리보기용 개발 서버 설정으로 새로 추가했다.
