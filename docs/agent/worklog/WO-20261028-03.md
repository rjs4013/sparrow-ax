### 요구 항목
- 승인된 제안: "공통 기반(스캐폴딩, DB, API 클라이언트)". 기능 구현(수집 · 필터 · View)은 이 지시서의 범위가 아니다.
  - 수용 기준: ① `npm run build` · `lint` · `test`가 통과하고 `scripts/gate.sh`가 이를 실제로 실행한다. ② DB가 빈 파일에서 마이그레이션으로 초기화된다. ③ API 클라이언트는 서비스키가 없으면 명확한 오류를 내고, 키 값이 오류 메시지에 노출되지 않는다. ④ 웹 서버가 `/health`에 응답한다.
  - 확인 방법: 위 각각을 단위 테스트로 고정한다.

### 가정
- 의존성은 최소로 한다: 런타임 `fastify`, `exceljs`(엑셀 단계에서 쓰므로 이번에는 설치하지 않는다 → 필요할 때 추가), 개발 `typescript`, `@types/node`.
- 이번에 `exceljs`는 설치하지 않는다(요청 밖 기능 방지). 승인된 스택에는 포함돼 있으므로 엑셀 작업의 지시서에서 추가한다.
- TypeScript는 `tsc --noEmit`으로 타입만 검사하고, 실행은 Node의 타입 제거 기능(`node --experimental-strip-types` 불필요, Node 24 기본)으로 한다. 따라서 코드는 `import type`과 확장자 `.ts` 포함 import를 쓴다.
- 테이블 스키마는 기능 지시서에서 정한다. 이번 DB는 마이그레이션 실행기와 `schema_migrations` 관리까지만 만든다.
- 실제 나라장터 API 호출은 하지 않는다. 엔드포인트와 응답 형식이 문서에 없어 확정이 필요하다(아래 미해결).

## 기록
- 변경 집합: 브랜치 feat/WO-20261028-03-scaffold (기준 `master` 91e7d8c)
- 설치된 주요 버전: Node v24.22.0, typescript 7.0.x, fastify 5.12.x, @types/node 24.x (lock 파일로 고정). 메이저 버전이 새것이라 의도한 버전인지 사람 확인을 요청한다.

### 작업 중 발견한 것
- 테스트가 **실제 보안 결함**을 먼저 잡았다: `URL`이 서비스키의 `%`를 `%25`로 인코딩해 넣기 때문에, 원문 키만 마스킹하면 오류 메시지의 URL에 인코딩된 키가 남았다. 응답 오류 메시지에는 키 없는 URL만 쓰고, 호출 실패 · JSON 파싱 오류는 원문 · 인코딩 두 형태를 모두 마스킹하도록 고쳤다.
- 자체 점검 중 서버 종료용으로 쓰려던 광범위한 프로세스 종료 명령이 자동 승인 분류기에 거부되었다(이 PC의 다른 node 프로세스에 영향 가능). 이후 확인은 `timeout`으로 스스로 끝나는 방식만 썼다.

### 검토 (reviewer, 별도 컨텍스트): 통과, 차단 사항 없음
수용 기준 ①~④ 충족, 서비스키 유출 경로 없음, 기본 HOST 127.0.0.1, 의존성 최소, 범위 밖 기능 없음, 문서 정합. 권고 처리:

| 권고 | 처리 |
|---|---|
| audit 단계 fail-open (`network` 단어로 건너뜀 처리) | **반영.** 오류 코드로만 판정하고 취약점 보고가 함께 있으면 실패. 건너뜀이 있으면 마지막 줄에 "통과 증거 아님" 표시. 샘플 3종으로 판정 확인 |
| 빈 키 방어, JSON 파싱 오류 래핑, Decoding 키 안내 | **반영** (테스트 포함) |

| 파일 DB 테스트, `localeCompare` → 코드 단위 정렬, ROLLBACK 보호 | **반영** (테스트 포함) |
